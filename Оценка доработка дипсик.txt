привести факты и счётчики в документации к прогону (есть расхождения);

разблокировать внешние контуры (ключи, deploy-секреты, staging, Android/сторы, бэкап);

1. Сначала — гигиена фактов. Это дешевле всего и важнее всего
1.1. Расхождение счётчиков тестов
Есть прямое противоречие между машинным инвентарём и доками:

Источник	Сервер	Фронт	Всего
test-inventory.json, server-tests.txt, frontend-tests.txt	2389 / 137 файлов	1563 / 122 файла	3952
Что доделать.txt, README.md, project-context.md, ИНВЕНТАРЬ-ТЕСТОВ.md	2423 / 139 файлов	1583 / 123 файла	4006
Разница — ровно 34 серверных и 20 фронтовых тестов, 2 и 1 файл. При этом гейтовые тесты совпадают (682 фронт / 122 сервер), а расходятся только продуктовые. Похоже, test/machine/* снят до добавления трёх продуктовых тест-файлов, а доки обновлены позже — либо наоборот.

Правило проекта: числа только из прогона node scripts/test-counter-audit.mjs, не из перепечатки. Поэтому первое действие:

bash
node scripts/test-counter-audit.mjs          # без --fix: увидеть, что именно красное
node scripts/test-counter-audit.mjs --fix    # переписать доки и machine-инвентарь
npm run check:mirrors                        # зеркала test/ побайтово
Затем закоммитить и доки, и test/machine/*. Если гейт действительно сверяет machine-файлы, он должен был покраснеть — значит, либо прогон не делался, либо файлы не закоммичены. Это подрывает главный принцип проекта «числа — только из гейта».

VAPID: приватный ключ скомпрометирован (коммит e8b26bf). Решение владельца — только регенерация на VPS (npx web-push generate-vapid-keys), историю не переписывать.

3. Кодовый бэклог, который можно делать без ключей (P1)
3.1. Native/WebView E2E — единственная заметная слепая зона
В e2e/ нет native*/capacitor* спека. Варианты:

добавить смоук на нативный адаптер/WebView (если это реально прогнать в CI);

либо явно зафиксировать как принятое ограничение с причиной (как сделано с cross-browser).

Сейчас это выглядит как «забыто», а не «осознанно отложено».

3.2. Покрытие: не гнаться за hangouts.js, идти в security/money
В бэклоге резерв назван так: hangouts.js 49% веток / 37 из 57 функций, admin/partners.js 46%, partner-dashboard.js 61%, social.js 63%, partners.js 65%, profile.js 67%, upload.js 49%.

hangouts.js — большой, но не самый рискованный. Приоритетнее:

upload.js — S3-ветка, удаление оригинала/вариантов, AI-вердикт; безопасность загрузок.

profile.js — приватность, блокировки, псевдонимы, watch-лист; там уже были IDOR/приватность-дефекты.

admin/partners.js — выплаты, статусы, processed_at; денежный контур.

partner-dashboard.js — подписка, checkout, вебхук, лимиты тарифов.

partners.js — postback, checkout, вебхук, идемпотентность.

social.js и hangouts.js — следующим эшелоном, если останется время. Гнаться за 100% по огромному hangouts.js дороже, чем закрыть дыры в загрузке/деньгах/приватности.

3.3. CI-усиление: check:bundle и check:console сейчас локальные
В «Принятых решениях» они локальные, но это решение стоит пересмотреть:

check:bundle дёшево добавить в frontend-джобу после vite build: бюджет initial JS/CSS перестанет регрессировать молча.

check:console — в e2e-джобу после поднятия стека 3002/8081: console-errors/pageerror/5xx на статических страницах будут ловиться в CI, а не только локально.

Это не «ещё один гейт ради гейта»: оба уже ловили реальные проблемы, но сейчас их может обойти любой PR.

3.4. Cross-browser — осознанное ограничение, но дешёвый ночной прогон не помешает
CROSS_BROWSER=1 включает firefox/webkit, по умолчанию только chromium. Можно добавить ночной/ручной workflow, не блокирующий PR. Это закроет риск «работает только в chromium» без удорожания каждого PR.

3.5. CSRF — не включать сейчас, но не потерять триггер
csrfGuard выключен до выноса API на поддомен; порядок активации записан в server/src/index.js. Достаточно не потерять это при выносе. Можно добавить тест-напоминание, который падает, если API уже на отдельном домене, а guard всё ещё выключен, — но это сложно сделать надёжно; как минимум держать пункт в «Принятых решениях».

3.6. bull/uuid 2 moderate — принято, не чинить силой
Замена BullMQ отклонена: требует Redis ≥ 6.2, а локальный запуск-всего.bat стартует Laragon Redis 5.0.14.1; живой смоук показал, что на 5.0 очереди создаются, но каждая операция падает Lua-ошибкой — джобы теряются молча. npm audit fix --force (понижение до bull@1.1.3) брать нельзя. Вернуться после апгрейда Redis или замены очереди.

3.7. Storybook / Design System — низкий приоритет
«Не начато», но по делу: понадобится, когда UI-изменения начнут ломать визуальную регрессию. Сейчас это не блокер.

6. Меры предосторожности при выполнении
Перезапускать API только через запуск-всего.bat или с его точной строкой env; иначе стенд тихо уходит в fallback, а E2E падают 503 «задним числом» (питфолл 106).

После npm audit fix --omit=dev — обязательно npm install, иначе dev-дерево (vitest) исчезнет и следующий прогон упадёт с ERR_MODULE_NOT_FOUND (питфолл 92).

Не откатывать ломки через git checkout --: это стирает незакоммиченную работу; делать байтовый снимок (питфолл 77).

Один агент на рабочее дерево; «файл появился/исчез сам» — это второй писатель, а не мистика (питфолл 95).

После правок доков — npm run check:mirrors (8 пар test/ побайтово), иначе зеркало протухнет.

Итог: самый ценный следующий шаг — не новый код, а Stage A: прогнать счётчики, починить README/инвентарь/зеркала и вычистить из бэклога закрытую историю. После этого станет видно реальный открытый список, и можно спокойно идти в Stage B–D.
