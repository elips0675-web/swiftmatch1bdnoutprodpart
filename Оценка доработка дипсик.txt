Ниже — оценка по фактическому состоянию документов (бэклог, инвентарь, AGENTS, README, Для анализа.txt). Разделил на «горит», «можно делать без ключей», «инфра/долг», «решения владельца» и «гигиена документов».

1. Что реально горит (P0): зелёное на бумаге ≠ проверенное
Полный живой E2E после этапов 45/46 не прогонялся.
В шапке бэклога прямо написано: E2E 205/205 — это статический счёт playwright --list; последний полный живой прогон — 12.10.2026 (152 в 19 спеках), а стенд 3002/8081 отдаёт код до 1fce1f1. После этапов 45/46 (платёжная сверка, P3 #26 UI, лимитеры, очереди) полного прогона не было.
Действие: перезапустить API через запуск-всего.bat, проверить GET /health (особенно redis: live), прогнать npm run test:e2e полностью. Пока этого нет — «2397/2397» относится только к vitest, а не к живому продукту.

CI-красноты 12.10.2026 формально «исправлены, ждут прогона».
В бэклоге до сих пор висит блок про server-test / test-counters / e2e / Trivy. Если последние прогоны в CI зелёные — пункт надо закрыть и удалить, иначе он создаёт ложное ощущение открытого дефекта. Если нет — это первый блокер деплоя.
Действие: посмотреть последний run ci.yml/deploy.yml; при зелёном — вычистить блок, при красном — чинить до всего остального.

Инвентарь тестов противоречит сам себе и содержит 3 заглушки.
В ИНВЕНТАРЬ-ТЕСТОВ.md всё ещё стоят ⚠️ требует описания у admin-experiments (14), admin-messaging (11), admin-monetization (12), хотя шапка бэклога утверждает, что заглушек 0. Плюс в том же файле: заголовок «срез 04.10.2026», таблица «Фронт — 76 файла, 516 теста», строка «всего 99 файлов = 1100 тестов» — при фактических 102 файлах / 1137 тестах (516 продукт + 621 гейты).
Действие: заполнить 3 описания, обновить шапку/итоги, прогнать node scripts/test-counter-audit.mjs --fix и npm run check:docs. По питфоллу 59 гейт должен падать на PLACEHOLDER_HINT — проверить, почему не упал (или файл в снимке старее гейта).

Для анализа.txt — протухший вход для внешних аудитов.
Он помечен «актуализировано 12.10.2026» и до сих пор перечисляет как открытые P3 #27 (field-level permissions) и M2 (Perspective), которые закрыты/сняты 15.10.2026. Внешняя модель добросовестно воспроизведёт ложные находки — это ровно питфолл 101 «корректирующий аудит против протухшего среза».
Действие: либо перегенерировать из текущего бэклога, либо явно переписать шапку: «исторический срез 12.10.2026, открытые пункты — только в Что доделать.txt».

2. Кодовый бэклог, который можно закрыть без ключей и VPS (P1)
Самое ценное — «находки батчей юнитов страниц». Там не абстракции, а проверенные по коду дефекты. Я бы сгруппировал их в один этап «UI не врёт»:

partner-dashboard.tsx — пауза оффера игнорирует res.ok: бейдж показывает paused, а на сервере оффер активен. Нужен ключ ошибки (сейчас его нет ни в RU, ни в EN).

admin-photos.tsx — отказ модерации молчит: тост только внутри if (res.ok), на 403/500/сети админ видит «нажал и ничего». Плюс причина отклонения зашита "Inappropriate content" — нужен список причин и i18n.

admin-backup.tsx — причина отказа сервера выбрасывается: body?.message читается и не показывается, админ видит общий admin.backup.error_create; размер всегда «MB» без разрядов (0.00 MB на 900 байт).

premium-success.tsx / partner-order-success.tsx — session_id читается и не используется: страница успеха рисуется по любому URL, оплата не подтверждается. Либо серверная проверка сессии, либо убрать чтение.

onboarding.tsx — три дефекта: отправляет zodiac: "" и затирает ранее заполненный знак; иконка сна сравнивает 'lark', а кнопки пишут early-bird/night-owl; кнопка AI-био подписана «AI Сохранить», а предупреждение при пустых интересах берёт текст шага 4.

search.tsx — два сентинела «все города» ("all" и "Все"), недостижимый диалог жалобы, кнопка «сменить фильтры» в обычном режиме нажимается в пустоту.

groups.tsx — третья копия списка запрещённых слов вместо containsForbiddenWords/сервера.

user.tsx — мёртвая ветка isSystem; partner-dashboard рисует partner.type сырым кодом вместо t(\partner.type_${type}`)`.

admin-analytics.tsx — ~10 сырых литералов без t() (MAU, Live, Real data from database, Retention Rate, % вернувшихся, Новые пользователи) — в EN-локали русские заголовки.

check-console.mjs не заходит в /premium/success, /premium/cancel, /partner/register, /partner/dashboard, /partner/order/* — поэтому validateDOMNesting в дашборде партнёра жил незамеченным. Добавить маршруты (нужен партнёрский storageState) или E2E-спек.

Отдельно: страницы без собственных юнитов остались только в админке — admin-teams, admin-content, admin-reports, admin-partners. admin-experiments/messaging/monetization файлы уже имеют, но с заглушками описаний. Это следующий логичный батч после «UI не врёт».

3. Тесты и гейты, которые просят закрытия (P1–P2)
Backup/restore smoke в CI: verify-backup.mjs подключён, а прогона «restore → smoke» нет. Это дешёвая джоба: поднять временную БД, восстановить дамп, прогнать 5–10 read-only смоуков.

Интеграционный прогон против docker-compose (MySQL + Redis + maildev): сейчас очереди живьём проверены только смоуком, а SMTP-флоу — только моками. Docker локально снят, но в CI runner сервисы доступны; maildev как service container закроет «письмо реально ушло в SMTP».

Порогов coverage нет ни в vitest.config.ts, ни в server/vitest.config.js (P3 #32). Начать можно с текущего факта минус 2 п.п., иначе правило «буфер +2 п.п.» мёртвое.

P3 #32 «покрытие ядра»: auth-context, use-premium, use-websocket, chats, hangout-detail — оптимистичные сценарии. Часть покрытия уже есть (8/5/14 тестов), но оптимистичные/откатные ветки — нет.

Cross-browser: CROSS_BROWSER=1 есть, но по умолчанию только chromium. Либо nightly-джоба на firefox/webkit по критическим спекам, либо зафиксировать как осознанное ограничение.

a11y системно не проверяется: aria-* точечно, axe-смоука нет. Дешёвый вариант — 5–7 ключевых страниц через @axe-core/playwright, локально или отдельной неблокирующей джобой.

Native/WebView E2E (Capacitor) — честно заблокирован устройством/Android Studio; не притворяться, что закрыт.

4. Инфра и зависимости (P2)
28 moderate в prod-зависимостях server/: @sentry/node 9→11 (цепочка OpenTelemetry), firebase-admin → 14.5.0, bull → advisory в uuid. npm audit fix --force даст понижение bull до 1.1.3 — нельзя. Нужен отдельный этап: обновить Sentry/Firebase, а bull заменить на BullMQ либо зафиксировать риск. Не срочно (0 high/critical), но это то, что тихо копится.

S3/CDN, SMS, AI-модерация, FCM, OpenAI, Rekognition — только mock/fallback. Без ключей не закрыть, но можно добавить контрактные тесты с локальными эмуляторами (MinIO для S3, maildev для SMTP), чтобы кодовая ветка была хоть раз исполнена не моком.

L1 VAPID — только ротация на VPS, решение владельца; кода не требует.

M4/csrfGuard — сознательно выключен; триггер «до первого реального платежа или выноса API на поддомен» стоит продублировать в runbook платежей, иначе «отложено» станет «забыто».

5. Продуктовые решения, которые блокируют код (P2)
M1 — окно чек-ина ±2 ч: константа удалена, маршрут время не проверяет. Нужно решение: вводить окно (риск опоздавших) или зафиксировать «без окна». Пока это не дефект, а незакрытое намерение.

«Все фото» в admin-photos: модерация доступна только в фильтре «на модерации». Похоже на замысел, но если «все» — основной экран, это ловушка. Решение владельца.

Диалог списка приглашений в user.tsx: не закрывается при открытии своего — возможно, так и задумано; закрыть как «не дефект» или поправить.

Storybook / Design System — не начато, низкий приоритет; брать, когда визуальная регрессия начнёт ломаться.

6. Гигиена документов: бэклог перестал быть бэклогом
Шапка Что доделать.txt — это огромный абзац, который пересказывает закрытые этапы 45/46, лимитеры, алерты, пагинацию, аудит фото и т.д. Формально правило «закрытое не живёт в бэклоге» соблюдено для таблиц/пунктов, но шапка превратилась в хронику. Последствия уже видны:

«Redis-сервер не поднят» в блокерах противоречит другим документам, где Redis live (Laragon 5.0.14.1, /health → redis: live, очереди 40/0 и 12/0). Надо проверить и убрать протухшее.

«CI ждёт прогона» от 12.10 соседствует с «гейты 28/28» и «23 джобы + 7».

«Закрыты 47 заглушек» — а в инвентаре 3 заглушки.

«E2E 205/205» — а это статический счёт, не живой прогон.

Действие: сократить шапку до 10–15 строк (дата, счётчики, состояние git, очередь, ссылки на журнал), историю — в Что сделано.txt. После правок: node scripts/test-counter-audit.mjs --fix, node scripts/check-doc-mirrors.mjs --fix, npm run check:docs, перегенерировать Что доделать коротко.txt полностью.

7. Что я бы не брал сейчас
Storybook/Design System — низкий приоритет.

Native/WebView E2E — заблокирован устройством.

Quiet hours/DND, SLA/business hours, custom roles, Kanban/Calendar/Wiki — «не брать» по консенсусу, не возвращать.
