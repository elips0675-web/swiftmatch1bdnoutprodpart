## 0. Как выбрать промт

| Ситуация | Промт |
|---|---|
| Понять, что мешает выпуску / «первому рублю» | **A** — «Вывод в прод» (стратегический) |
| Общая картина пробелов, поиск новых классов дефектов | **B1** — аудит слепых зон |
| Нашёл конкретную дыру — нужен гейт | **B2** — шаблон гейта |
| Закрыть дешёвый пробел навигации | **B3** — E2E-смоук (в основном сделано, см. §D) |
| Внешний блокер — Google Play | **B4** — готовность к публикации |
| Не доверяю документации | **B5** — метапромт-скептик |
| Быстрые фактические правки в доках | **B6** — правка фактов |
| Не хочу выбирать — нужен один промт | **C** — «один на всё» |

### 0.1. Три правила к любому промту

1. **Пункт без `file:line` — не факт.** Требуй от модели цитату кода/строки; иначе вернётся пересказ
   чужого аудита (питфолл «пересказ чужой оценки воспроизводит её числа»).
2. **«Skip» помечай явно.** Иначе модель сделает необязательное и сломает соседнее (`docs/AGENTS-workflow.md`).
3. **Проверка ломкой.** Если промт добавляет гейт — требуй доказательство, что гейт краснеет на сломанном
   входе (питфолл «ломка гейта, которая ломает не то, доказывает ноль»).

### B2. «Гейт для класса дефектов» (когда нашёл дыру)

Шаблон под конкретную находку. Пример подставлен под log rotation.

```text
Добавь в проект SwiftMatch гейт на [КЛАСС ДЕФЕКТА].

Стек: Node, Express, существующие гейты в scripts/*.mjs, тесты гейтов в scripts/*.test.mjs,

Требования к гейту (по правилам проекта из docs/AGENTS-pitfalls.md):
1. Гейт обязан ПАДАТЬ на сломанном входе — докажи ломкой

2. У гейта свои тесты в scripts/<name>.test.mjs (>=8 тестов)
3. Wiring проверяется тестом: джоба в ci.yml + шаг в deploy.yml, джоба не continue-on-error, не if:false
4. Регулярки с якорями ^/$ — только с флагом m, либо без якорей
5. Границы блока вычисляются явно — не окном строк

   с тестами на обе противоположные пары
```

## C. Один промт «на всё»

Скопируй это в сильную модель и приложи `Для анализа.txt`:

```text
Ты работаешь с проектом SwiftMatch. Приложен снимок.

Сделай два прохода:

ПРОХОД 1 — скептик:
Найди 5 мест, где документация обогнала реальность («сделано» без кода, противоречия между файлами,
гейты-декорации, долг в комментарии без записи в бэклог). По каждому: цитата документа + цитата кода +
что на самом деле.

ПРОХОД 2 — планировщик:
Из этих 5 плюс из моего списка ниже выбери 5 самых дешёвых по «риск × стоимость фикса».
Для каждого: файлы, строки, тест (имя файла), нужен ли гейт.

Мой список (проверь каждый, дай вердикт есть/нет/неизвестно с file:line):
- SIGINT и сторожевой таймаут shutdown
- Trivy exit-code (baseline, не блокирует деплой)
- Log rotation для server/logs/api.log
- Rate limit на POST сообщения чата
- Rate limit на AI-эндпоинты (icebreakers, hangouts/suggest)
- Alerting rules в Prometheus
- Reconciliation Stripe (пропущенный webhook)
- Subscription lifecycle (expire/cancel/refund)
- Timezone для TIMESTAMP/DATETIME (не только DATE)
- Soft-delete cascade / сироты без ON DELETE
- GDPR erasure в бэкапах
- Native-тесты (WebView/Capacitor)
- a11y
- SPF/DKIM/DMARC
- Privacy Policy / Terms (блокирует Google Play)
- Referral/Contest/Schedule/Attachment — тесты

Формат: две таблицы, без воды. Пункт без file:line — [гипотеза].
```

Этот последний промт — оптимальный старт: он одновременно ловит дрейф документов и даёт план.
