Датинг-платформа (Tinder-like) + соцфункции: React 18 + TS + Vite 8 фронт,

(vite proxy /api→3002), API+WS 3002, MySQL 3306, Redis 6379.

## Безопасность (текущая модель)

- **JWT в httpOnly cookie** `sm_token` (15m) + `sm_refresh` (7d): SameSite=Lax, Secure в production.
  Ставятся на login/register/refresh/dev-login (`server/src/cookies.js`).
- Все auth-мидлвари читают **Bearer ?? cookie** (`extractToken`) — нативные сборки работают через Bearer.
- Web-фронт НЕ пишет токен в JS-доступный storage (XSS-safe), читает легаси-storage для совместимости;
  refresh через POST с пустым body (сервер берёт куку), защита от цикла (flag `refreshed`);
  `GET /api/auth/me` — probe, всегда 200 `{authenticated:false}` без сессии;
  `POST /api/auth/logout` — чистит куку + удаляет refresh-токен из БД.
- **Refresh rotation + reuse detection (этап 34)**: каждый refresh-токен принадлежит `family_id`;
  ротация атомарно отзывает старый токен и выдаёт новый в той же семье; replay ротированного =
  компрометация → отзыв всей семьи. Гонка параллельных refresh закрыта atomic claim'ом.
- **Revoke all sessions**: POST `/api/auth/logout-all`; смена пароля (reset-password) отзывает все сессии юзера.
- **Account lockout**: 5 неудачных логинов подряд на email → 429 на 15 мин (`server/src/lockout.js`, env `AUTH_LOCKOUT_MAX_ATTEMPTS`).
- **Санитизация ввода**: пользовательский текст хранится без HTML-тегов (`stripHtml` в profile PUT, register, постах групп, сообщениях; «<3» и «a<b» не ломаются). В коде нет dangerouslySetInnerHTML — React экранирует рендер.
- WS handshake принимает токен только из `handshake.auth.token` (query-param убран).
- CSRF: SameSite=Lax + строгий CORS_ORIGIN (fail-fast в production без него).
  Полные CSRF-токены отложены до выноса API на отдельный домен (осознанное решение, см. AGENTS Security Rules);
  Admin TOTP 2FA (otplib) — **сделано** (см. этапы 35–45 ниже); fingerprinting сессий — сделано.
- Helmet (CSP и др.), request-id, Sentry c PII-фильтром в beforeSend, Winston без тела запросов.
- Rate-limit: глобальный 600/мин, лайки 30/мин, auth 60/мин (поднят для E2E) + лок-аут логина.
- Модерация: banned-words в чатах, auto-escalation репортов (3+ → temp ban, severe → мгновенный).

## Инфраструктура

- CI/CD GitHub Actions (`ci.yml` + `deploy.yml`): lint (фронт+сервер) → front tests → server tests (MySQL-сервис) → E2E → docker-config-check → deploy;
  деплой Docker: `appleboy/ssh-action` → `docker compose up -d --build` → миграции, `schema-validate` и `schema-drift` В КОНТЕЙНЕРЕ (`docker compose exec -T app …`).
- Redis: кэш (profile 60s, matches 30s), Bull Queue (email/push/image), Socket.IO adapter; graceful fallback.
- Мониторинг: Prometheus :9090 + Grafana :3001 (7 панелей), prom-client метрики HTTP/DB/WS/cache.
- Docker Compose: app + nginx + Prometheus + Grafana (YAML валиден; Docker Desktop 29.8.2 + Compose v5.5.1 стоял на 12.10.2026, но откат Windows 13.10.2026 его снял — локальная сборка/прогон образов сейчас недоступны).
- Nginx conf: rate-limit, WS 86400s, SSL, SPA fallback. Бэкапы MySQL: скрипты PS/sh + Task Scheduler 03:00, retention 7d.
- k6: лайт-прогон 10 VU ок (p95 ≤ 232ms, 57% «ошибок» = rate-limit by design); полный 100 VU — на staging.
