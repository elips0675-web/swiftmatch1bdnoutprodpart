## 🟡 P2 — nice-to-have, дошлифовка

### M1. Чек-ин не ограничен окном времени (продуктовое решение)

`server/src/routes/hangouts.js` — мёртвая `const CHECKIN_WINDOW_HOURS = 2` из кода удалена (поиск по `server/` — 0 совпадений), а маршрут `POST /api/hangouts/:id/checkin` (`:1595`) не проверяет время встречи вообще: ограничен только радиусом `CHECKIN_RADIUS_M = 500` (`:1290`, проверка в `:1612`). Что делать: (а) ввести окно ±2 ч — риск продуктовый, опоздавшие перестанут отмечаться; (б) оставить как есть — константы в коде нет, намерение зафиксировано. Решение за владельцем.

**Поправка 15.10.2026 (сверка свода оценок):** прежние цитаты этого пункта — `:966` (константа), `:965` (радиус), `:1216` (маршрут), `:1233` (проверка) — протухли: ни одна не указывала на то, о чём говорила, и внешние оценки цитировали их как проверенный факт (питфолл «оправдание гейта по номеру строки протухает молча»).

### M4. `csrfGuard` импортирован, но смонтирован быть не может (сознательное решение)

`server/src/index.js:104-107` — `// app.use(csrfGuard)` закомментирован с пояснением «после выноса API на поддомен». Импорт убран, в комментарий вписано «вернуть в импорт». Пока API на том же домене, решение верное; при выносе на поддомен guard **обязан** быть включён, иначе cookie-сессии станут уязвимы к CSRF. **Триггер, чтобы «отложено» не стало «забыто»** (предложение свода оценок): guard включается **до первого реального платежа** или при выносе API на отдельный поддомен — что наступит раньше; до этого `SameSite=Lax` + CORS считаются достаточными.

## Правила работы с журналами и бэклогом

- **Бэклог ≠ история.** Новые закрытые пункты пишутся в `Что сделано.txt` (хроника этапов); из бэклога закрытый пункт удаляется — закрытая строка таблицы или пункт с телом ловится гейтом (`backlog-closed-line`), как и тело под закрытым заголовком (`backlog-closed-body`); в бэклоге остаётся только заголовок-маркер без тела. Полная история прошлых срезов — в `docs/agenda-archive.md`.
- **Числа в шапках** — только прогоном `node scripts/test-counter-audit.mjs` (exit 0), не перепечаткой: гейтом покрыты 8 файлов — `README.md`, `project-context.md`, `test/ИНВЕНТАРЬ-ТЕСТОВ.md`/`test/README.md`/`test/project-context.md`/`test/Для анализа.txt` и шапки `Что сделано.txt` / `Что доделать.txt` (карта `DOCS` в `scripts/test-counter-audit.mjs`).
- **Зеркало `test/Что доделать.txt`** синхронизируется с корнем побайтово после каждой правки бэклога (история `Что сделано.txt` в `test/` не зеркалируется: `test/` — компактный набор для внешнего AI-анализа).
- **Кодировка:** править файлы node-скриптами + `cmd /c "node ... > file 2>&1"`, затем читать файл (PowerShell ломает кириллицу).
- **Пункт без цитаты кода** (`file:line`-цитата, проверенная по коду) в бэклог не попадает.
- **Дата проверки обязательна, объём ограничен:** строка-пункт таблицы с ID без `ДД.ММ.ГГГГ` в колонке «Проверено» роняет `check:docs` (`backlog-item-verified`), как и раздувание бэклога сверх 1500 строк / 120 КБ (`backlog-max-lines`).
- **Фича = флаг** (по умолчанию off, включение через админку); DoD: флаг + тест + i18n + `check-console` + актуальный инвентарь тестов.
- **Сначала фикс, потом тест:** тест, фиксирующий баг, пишется после устранения причины.
- **Пороги coverage — буфер +2 п.п.** ниже фактического.
- **Промты про БД** требуют идемпотентные миграции (без ручных ALTER вне миграций), обновление `schema.prisma`/эталона, индекс при необходимости, обратную совместимость.
