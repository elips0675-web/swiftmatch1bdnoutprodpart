На основе анализа предоставленных файлов (AGENTS-security.md, AGENTS.md, AGENTS-production.md, Что доделать.txt, AGENTS-pitfalls.md) по состоянию на 20 октября 2026 года, проект находится в высокой степени готовности. Подавляющее большинство задач P0/P1/P2 (включая покрытие тестами, дрейф схем, E2E-очистку и гейты CI) успешно закрыты (этапы 60–118).
Однако для полного завершения и вывода в продакшен остаются следующие направления доработок, разделенные по приоритетам:
🚨 1. Критические блокеры (Ждут действий пользователя / Внешние зависимости)
Эти пункты невозможно решить только кодом, они требуют вмешательства владельца/администратора:
Отсутствие реальных ключей в server/.env: Проект работает на mock/fallback. Необходимы: STRIPE_SECRET_KEY, STRIPE_WEBHOOK_SECRET, SMTP_USER/PASS, SENTRY_DSN, AWS_*/S3_BUCKET, OPENAI_API_KEY, FCM_SERVER_KEY, REVENUECAT_WEBHOOK_SECRET, TWILIO_*.
Секреты GitHub для deploy.yml: Отсутствуют DEPLOY_HOST, DEPLOY_USER, DEPLOY_SSH_KEY, DB_*. Из-за этого падает шаг rsync в пайплайне деплоя (единственная красная джоба в последних прогонах).
Бэкап и зеркало (Диск E: недоступен): Локальное bare-зеркало E:\swiftmatch-backup.git и облачные бэкапы (bundle, zip, дамп MySQL через backup-mysql.ps1) не обновляются. Это риск потери истории и данных.
Ротация VAPID-ключей (L1): Приватный ключ был скомпрометирован (коммит e8b26bf). Требуется регенерация пары ключей непосредственно на VPS (npx web-push generate-vapid-keys) и замена в /app/swiftmatch/.env. Историю git переписывать запрещено.
🟡 2. Очередь доработок (P2/P3 Бэклог)
После разблокировки окружения можно приступать к следующим задачам:
А. Точечное улучшение покрытия сервера (Резерв)
Ядро и инфраструктура сервера закрыты (факт ~93%, пороги 90/88/89/91). Остаток – это целенаправленное добивание веток в крупных роутерах, где покрытие ниже 70%:
hangouts.js (~49% веток)
admin/partners.js (~46%)
partner-dashboard.js (~61%)
social.js (~63-65%)
profile.js (~67%)
upload.js (~49%)
Б. Техдолг второй очереди (Интеграции, требующие ключей)
Код и контрактные смоуки (mock) уже готовы, требуется только подключение реальных сервисов:
SMS-верификация: Scaffold и mock готовы, ждет ключей Twilio.
AI-модерация фото: Клиент Rekognition и fallback-эвристика готовы, ждут AWS-ключей.
CDN/S3: Режим переключения готов (USE_S3), ждет конфигурации S3-бакета.
Push FCM: Job отправки готов, ждет FCM_SERVICE_ACCOUNT (принимает base64/JSON/путь).
CSRF-защита: csrfGuard готов, но сознательно отключен. Должен быть включен одной строкой только при выносе API на отдельный поддомен.
Мониторинг и SSL: Настройка UptimeRobot и SSL внутри docker-compose для staging/production.
В. Внешнее тестирование
IAP Sandbox: Тестирование покупок в Google Play Sandbox заблокировано внешне до публикации приложения в сторе.
Android: Сборка APK, реальное устройство, App Links (домен + assetlinks.json, SHA256).
🛡️ 3. Производственная готовность (Постоянный контроль)
При любых дальнейших изменениях строго соблюдать Pre-flight Checklist (AGENTS-production.md):
Golden Rule: Production ≠ File Created. Любая фича = Feature Flag + тест + i18n + check:console + актуальный инвентарь тестов.
Безопасность:
Никогда не коммитить .env с секретами (.env.example — в репо).
adminAuth должен оставаться ACTIVE (единый гейт /api/admin, публичен только GET /api/admin/features).
Все SQL-запросы только через prepared statements (??).
Пользовательский текст обязательно проходит через stripHtml.
Платежи: Новые платные точки обязаны иметь refuseMockPayment(res) в проде (fail-closed, возврат 503 {code:'STRIPE_NOT_CONFIGURED'}).
Синхронизация: После любых правок в документации запускать node scripts/check-doc-mirrors.mjs --fix для побайтового зеркалирования в папку test/.
❌ 4. Что НЕ нужно делать (Антипаттерны и отклоненные решения)
Чтобы не тратить время впустую, строго запрещено или нецелесообразно:
npm audit fix --force для bull: Понижение до 1.1.3 сломает работу с локальным Redis 5.0.14.1 (требуется для запуск-всего.bat). Advisory умеренный, достижимость низкая, оставляем bull@4.16.5.
Внедрение Enterprise-фич: SLA, business hours, кастомные роли (5 ролей достаточно), Kanban/Calendar/Wiki/Polls/News (отклонено для дейтинг-контекста).
Создание третьих копий правил: Все правила живут только в AGENTS.md и docs/AGENTS-*.md. Файлы типа Промты.txt – это только указатели, а не источник истины.
Ручные ALTER TABLE: Новые колонки добавляются только через миграции в database/migrations/.
