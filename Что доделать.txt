## 🟡 P2 — nice-to-have, дошлифовка

### L2. Расхождение двух хостовых nginx-конфигов

В образ едет `nginx/swiftmatch.http.conf` (`Dockerfile:30`). Два других файла — конфиги **хостового** nginx на VPS, и они расходятся:

| Файл | Роль | Расхождения |
|---|---|---|
| `nginx/swiftmatch.http.conf` | образ, HTTP:80 | `limit_req` 60r/s (`/api`) и 10r/s (`/api/auth`), `client_max_body_size 20M`, `proxy_read_timeout 86400s`, `location = /healthz` |
| `nginx/swiftmatch.conf` | хост, TLS:443 | 30r/s и 5r/s, `10M`, нет WS-таймаута |
| `nginx.conf` (корень) | хост, TLS:443 | **нет `limit_req` вообще**, **нет `client_max_body_size`**, `proxy_read_timeout 60s` |

Не выбрано, какой из двух хостовых конфигов — эталон. Риск: хост с `nginx.conf` не ограничивает скорость запросов и рвёт WS на 60-й секунде. Требует решения владельца и правок в документации под выбранный файл.

### M1. Чек-ин не ограничен окном времени (продуктовое решение)

`server/src/routes/hangouts.js:966` — `const CHECKIN_WINDOW_HOURS = 2` была мёртвой: маршрут `POST /api/hangouts/:id/checkin` (`:1216`) не проверяет время встречи вообще, ограничен только радиусом `CHECKIN_RADIUS_M = 500` (`:965`, проверка в `:1233`). Что делать: (а) ввести окно ±2 ч — риск продуктовый, опоздавшие перестанут отмечаться; (б) оставить как есть и удалить константу. Решение за владельцем; в коде константы уже нет, намерение зафиксировано.

### M2. Модерация Perspective не реализована, хотя ключ читался (P2)

`server/src/ai-moderation.js:7` читал `PERSPECTIVE_API_KEY = process.env.PERSPECTIVE_API_KEY` и **ни разу** его не использовал; `docs/environment-setup.md:64` и `test/СВОДКА.md:1348` описывали переменную как рабочую («модерация fail-open»). Чтение удалено (оно было мёртвым). Если нужна модерация Perspective — это новая интеграция с отдельным счётом и тестами, а не «дописать строчку».

### M4. `csrfGuard` импортирован, но смонтирован быть не может (сознательное решение)

`server/src/index.js:92` — `// app.use(csrfGuard)` закомментирован с пояснением «после выноса API на поддомен». Импорт убран, в комментарий вписано «вернуть в импорт». Пока API на том же домене, решение верное; при выносе на поддомен guard **обязан** быть включён, иначе cookie-сессии станут уязвимы к CSRF.

## Правила работы с журналами и бэклогом

- **Бэклог ≠ история.** Новые закрытые пункты пишутся в `Что сделано.txt` (хроника этапов); из бэклога закрытый пункт удаляется или помечается ✅. Полная история прошлых срезов — в `docs/agenda-archive.md`.
- **Числа в шапках** — только прогоном `node scripts/test-counter-audit.mjs` (exit 0), не перепечаткой: гейтом покрыты 7 файлов — `README.md`, `project-context.md`, `test/ИНВЕНТАРЬ-ТЕСТОВ.md`/`test/README.md`/`test/project-context.md` и шапки `Что сделано.txt` / `Что доделать.txt` (карта `DOCS` в `scripts/test-counter-audit.mjs`).
- **Зеркала `test/Что доделать.txt` и `test/Что сделано.txt`** синхронизируются с корнем побайтово после каждой правки журналов.
- **Кодировка:** править файлы node-скриптами + `cmd /c "node ... > file 2>&1"`, затем читать файл (PowerShell ломает кириллицу).
- **Пункт без цитаты кода** (`file:line`-цитата, проверенная по коду) в бэклог не попадает.
- **Фича = флаг** (по умолчанию off, включение через админку); DoD: флаг + тест + i18n + `check-console` + актуальный инвентарь тестов.
- **Сначала фикс, потом тест:** тест, фиксирующий баг, пишется после устранения причины.
- **Пороги coverage — буфер +2 п.п.** ниже фактического.
- **Промты про БД** требуют идемпотентные миграции (без ручных ALTER вне миграций), обновление `schema.prisma`/эталона, индекс при необходимости, обратную совместимость.
