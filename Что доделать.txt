## Правила работы с журналами и бэклогом

- **Бэклог ≠ история.** Новые закрытые пункты пишутся в `Что сделано.txt` (хроника этапов); из бэклога закрытый пункт удаляется — тела закрытых пунктов ловит гейт `backlog-closed-line`, тело под закрытым заголовком — `backlog-closed-body`. В бэклоге остаётся только заголовок-маркер без тела. Полная история прошлых срезов — в `docs/agenda-archive.md`.
- **Числа в шапках** — только прогоном `node scripts/test-counter-audit.mjs` (exit 0), не перепечаткой: гейтом покрыты 8 файлов — `README.md`, `project-context.md`, `test/ИНВЕНТАРЬ-ТЕСТОВ.md`/`test/README.md`/`test/project-context.md`/`test/Для анализа.txt` и шапки `Что сделано.txt` / `Что доделать.txt` (карта `DOCS` в `scripts/test-counter-audit.mjs`).
- **Зеркало `test/Что доделать.txt`** синхронизируется с корнем побайтово после каждой правки бэклога (`npm run check:mirrors --fix`; история `Что сделано.txt` в `test/` не зеркалируется: `test/` — компактный набор для внешнего AI-анализа).
- **Кодировка:** править файлы node-скриптами + `cmd /c "node ... > file 2>&1"`, затем читать файл (PowerShell ломает кириллицу).
- **Пункт без цитаты кода** (`file:line`-цитата, проверенная по коду) в бэклог не попадает. Дата проверки обязательна, объём ограничен: строка-пункт таблицы с ID без `ДД.ММ.ГГГГ` в колонке «Проверено» роняет `check:docs` (`backlog-item-verified`), как и раздувание бэклога сверх 1500 строк (`backlog-max-lines`).
- **Фича = флаг** (по умолчанию off, включение через админку); DoD: флаг + тест + i18n + `check-console` + актуальный инвентарь тестов.
- **Сначала фикс, потом тест:** тест, фиксирующий баг, пишется после устранения причины и зелён с первого прогона.
- **Пороги coverage — буфер −2 п.п.** ниже фактического: `npm run test:coverage` в корне и в `server/`, пороги в `vitest.config.ts` / `server/vitest.config.js`; локальные, в CI не заведены (как `check:console`/`check:bundle`). На 20.10.2026 фронт 72.73 / 79.7 / 68.74 / 72.73 % → пороги **70 / 77 / 66 / 70** (Stage 119: «факт − 2» = 70.73 / 77.7 / 66.74 / 70.73 — пороги без изменений; Stage 77 поднял ветки 76 → 77 и функции 64 → 66). Сервер 92.94 / 90.06 / 91.8 / 93.23 % → пороги **90 / 88 / 89 / 91**. Снижать пороги нельзя — только вверх.
- **Промты про БД** требуют идемпотентные миграции (без ручных `ALTER` вне миграций), обновление `database/mysql_schema.sql`, индекс при необходимости, обратную совместимость.
