## Что убрано и почему

- **Правила не дублируются.** Пересказ правил в этом файле был слабее канона и
  протухал отдельно от него: агент, читавший `Промты.txt`, получал текст,
  который уже не соответствует коду.
- **Промты «починки» уже сделанных багов** (разделы 7 и 8) — выполнены,
  оставлены только строкой выше со ссылкой на текущее состояние.
- **Числа тестов из промтов выброшены:** они устаревают молча, а числа в проекте
  живут под гейтом `test-counter-audit`.
- **Продуктовые идеи не потеряны:** они целиком в `docs/product-roadmap.md`,
  файл отслеживается в git и проверяется гейтом мусора в кодировке.

## Как это проверяется

`node scripts/docs-canon-audit.mjs` (npm-скрипт `check:docs`) падает, если:

1. в этом файле снова появятся разделы `## 0.`–`## 20.` или пропадёт шапка;
2. в таблице канона ссылка на несуществующий файл;
3. `docs/product-roadmap.md` потеряет хотя бы один из 14 заголовков разделов 21–34;
4. в отслеживаемых документах появится нормативное требование сделать
   `adminAuth` пассивным (правило — ACTIVE) или упоминание удалённой зависимости
   `zod` как установленной;

## X. Что ещё нужно проверить (приоритетно для этого проекта)

> Источник тестовой приоритизации: это не перечень "всех возможных тестов", а список реально недостающих проверок, которые закрывают риск на проде. Если AI используется в конкретном сценарии — тесты нужны; если AI не участвует — фокус на функциональные регрессии и продовые сценарии.

### Критично и без этого нельзя выпускать

1. **Auth / session / refresh**
   - refresh rotation + reuse detection + family invalidation;
   - cookie vs Bearer в дев/прод и нативной сборке;
   - logout-all / revoke-on-password-change;
   - lockout после 5 неудачных входов.
2. **Payments / subscriptions / webhooks**
   - Stripe checkout success/failure/replay;
   - webhook idempotency и double-delivery;
   - RevenueCat / IAP live path после ключей;
   - `STRIPE_NOT_CONFIGURED` fail-closed в prod без ключей.
3. **Uploads / photos / S3**
   - local vs S3, resize/cleanup, dead links, deletion cleanup;
   - moderation flow safe/unsafe/null;
   - file size, mime validation and permission boundaries.
4. **Push / notifications / WS**
   - delivery to real devices, quiet hours, unread counters, WS reconnect and session reverify;
   - fallback when push provider is unavailable.
5. **Hangouts / partners / booking**
   - create → response → accept → chat flow;
   - capacity, date validation, payment gating, partner deeplink and bookings;
   - permissions for one user to another user’s offer or private data.
6. **Admin + moderation**
   - ban/unban/impersonation, audit logs, moderation queues, report flow, admin-auth scopes.

### AI / prompt проверки — только там, где AI реально используется

- `icebreakers` / suggest flows: openai empty, timeout, fallback to DB, language switching.
- `hangouts suggest` / AI matching: fallback path, prompt sanitation, empty content, unknown data.
- `moderateText` / `moderateImage`: unsafe vs safe vs null; fail-closed without keys.
- `profile bio` / content generation injections: prompt injection boundaries, sanitized output, no raw HTML.

### Можно отложить, но не забыть

- cross-browser smoke;
- mobile native WebView-only spec;
- deep analytics style assertions, not critical for first release;
- broad Storybook/design-system pass;
- cosmetic i18n exhaustiveness beyond live routes.

### Порядок запуска

1. auth/session/refresh;
2. payments + webhooks;
3. upload + S3 + moderation;
4. push/WS;
5. hangouts/partners/booking;
6. admin/moderation;
7. AI/prompt tests only for actual AI entry points.

### Критерий готовности

Релиз нельзя считать готовым, пока не зелёные:
- 1) живой smoke auth/session/refresh;
- 2) live payment webhook smoke;
- 3) upload + moderation smoke;
- 4) push + notification smoke;
- 5) one full happy-path E2E for key monetization and matching flow.
